# 基于 Spring Boot 的废旧物品再利用平台开发规则

## 1. 项目概述

本项目是一个基于 Spring Boot 的废旧物品再利用平台，旨在为用户提供一个便捷、安全的废旧物品交易渠道，促进资源的循环利用，减少环境污染。

## 2. 代码规范

### 2.1 Java 代码规范

#### 2.1.1 命名规范
- **类名**：使用大驼峰命名法，如 `UserController`
- **方法名**：使用小驼峰命名法，如 `getUserInfo`
- **变量名**：使用小驼峰命名法，如 `userId`
- **常量名**：使用全大写字母，单词间用下划线分隔，如 `MAX_PAGE_SIZE`
- **包名**：使用小写字母，单词间用点分隔，如 `com.example.campussecondhand.controller`

#### 2.1.2 代码风格
- 缩进：使用 4 个空格进行缩进
- 行宽：每行代码不超过 120 个字符
- 空行：在方法之间、逻辑块之间添加适当的空行
- 注释：对复杂的逻辑和关键方法添加详细的注释

### 2.2 JavaScript 代码规范

#### 2.2.1 命名规范
- **变量名**：使用小驼峰命名法，如 `userInfo`
- **函数名**：使用小驼峰命名法，如 `loadUserProfile`
- **常量**：使用全大写字母，单词间用下划线分隔，如 `API_BASE_URL`
- **组件名**：使用大驼峰命名法，如 `ProductCard`

#### 2.2.2 代码风格
- 缩进：使用 2 个空格进行缩进
- 行宽：每行代码不超过 100 个字符
- 空行：在函数之间、逻辑块之间添加适当的空行
- 注释：对复杂的逻辑和关键函数添加详细的注释

## 3. 项目结构规范

### 3.1 后端项目结构

```
src/main/java/com/example/campussecondhand/
├── common/         # 通用工具类和常量
├── config/         # 配置类
├── controller/     # 控制器
├── dto/            # 数据传输对象
├── entity/         # 实体类
├── exception/      # 异常处理
├── repository/     # 数据访问层
├── service/        # 服务层
├── util/           # 工具类
└── CampusSecondhandApplication.java  # 应用程序入口
```

### 3.2 前端项目结构

```
src/
├── api/            # API 调用
├── components/     # 通用组件
├── images/         # 图片资源
├── router/         # 路由配置
├── stores/         # 状态管理
├── views/          # 页面组件
├── App.vue         # 应用根组件
└── main.js         # 应用入口
```

## 4. 开发流程

### 4.1 需求分析
- 明确功能需求和非功能需求
- 编写需求文档
- 与团队成员讨论需求

### 4.2 系统设计
- 架构设计：确定系统的整体架构和技术栈
- 数据库设计：设计数据库表结构和关系
- UI 设计：设计用户界面和交互流程

### 4.3 编码实现
- 分模块进行代码实现
- 遵循代码规范和命名约定
- 编写单元测试

### 4.4 测试验证
- 功能测试：验证系统各功能模块是否正常工作
- 性能测试：测试系统在不同负载下的响应时间和稳定性
- 安全测试：测试系统的安全性，包括认证、授权和数据保护
- 用户体验测试：评估系统的易用性和用户体验

### 4.5 部署上线
- 部署系统到服务器
- 进行用户测试
- 收集用户反馈

### 4.6 维护优化
- 根据用户反馈进行系统优化
- 修复系统漏洞和bug
- 定期更新系统功能

## 5. 代码审查

### 5.1 审查流程
1. 开发人员提交代码到版本控制系统
2. 团队成员进行代码审查
3. 提出修改意见
4. 开发人员修改代码
5. 再次提交代码进行审查
6. 代码审查通过后合并代码

### 5.2 审查内容
- 代码质量：代码是否符合规范，是否存在冗余代码
- 功能实现：功能是否按照需求实现
- 安全性：代码是否存在安全漏洞
- 性能：代码是否存在性能问题
- 可维护性：代码是否易于维护和扩展

## 6. 测试规范

### 6.1 单元测试
- 对关键方法和功能进行单元测试
- 使用 JUnit 进行后端单元测试
- 使用 Vitest 进行前端单元测试

### 6.2 集成测试
- 测试系统各模块之间的集成
- 测试 API 接口的调用
- 测试数据库操作

### 6.3 系统测试
- 测试整个系统的功能
- 测试系统的性能和稳定性
- 测试系统的安全性

## 7. 部署流程

### 7.1 后端部署
1. 构建项目：`mvn clean package`
2. 上传构建产物到服务器
3. 启动应用：`java -jar campussecondhand.jar`

### 7.2 前端部署
1. 构建项目：`npm run build`
2. 上传构建产物到服务器
3. 配置 Nginx 或其他 Web 服务器

## 8. 安全规范

### 8.1 认证与授权
- 使用 JWT 进行用户认证
- 实现基于角色的访问控制
- 定期更新密钥

### 8.2 数据安全
- 对敏感数据进行加密存储
- 防止 SQL 注入攻击
- 防止 XSS 攻击
- 防止 CSRF 攻击

### 8.3 API 安全
- 对 API 接口进行访问控制
- 限制 API 调用频率
- 对 API 响应进行安全处理

## 10. 版本控制

### 10.1 分支管理
- `main`：主分支，用于发布稳定版本
- `develop`：开发分支，用于集成新功能
- `feature/*`：功能分支，用于开发新功能
- `bugfix/*`：修复分支，用于修复bug

### 10.2 提交规范
- 提交信息应清晰明了
- 提交信息应包含提交的目的和内容
- 提交信息应使用中文或英文
